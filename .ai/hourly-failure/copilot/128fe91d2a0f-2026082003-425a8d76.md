### RC-2 — GPT/Codex `bwrap` loopback sandbox failure (PROVEN)

**Evidence:**  
- Job 96301731834, step 9 exited non-zero; contract validation immediately threw `FileNotFoundError: .strategy_cycle/gpt.json` (logged `2026-08-20T03:16:32.089Z`).  
- `OPENAI_PRESENT=true` — API key is present; failure is not a missing credential.  
- Issue description records: "Codex local command sandbox / `bwrap`, loopback `RTM_NEWADDR`, and failure writing `.strategy_cycle/gpt.json`".  
- `codex exec --sandbox workspace-write` uses `bwrap` (Bubblewrap) on Linux for namespace isolation. GitHub Actions `ubuntu-latest` runners block the unprivileged user-namespace and `RTM_NEWADDR` netlink required by `bwrap` to configure the loopback interface inside its sandbox. `bwrap` fails at setup; Codex never starts; no output file is written.  
- `gpt_error.txt` was empty (recovery used "GPT step failed without stderr"), confirming `bwrap` failure occurred before any stderr was captured by the redirect.

**Root cause:** `bwrap` cannot create a loopback interface in a nested namespace on the GitHub Actions runner, causing Codex to abort before any output is written.

**Impact:** GPT report is `INCOMPLETE` on every cycle run with the current `--sandbox workspace-write` invocation.

**Corrective action:** Replace `--sandbox workspace-write` with `--sandbox none` (rely on job-level sandbox), OR replace the Codex CLI call with a direct OpenAI Python API call (as the standalone Gemini step in `hourly-gemini-strategy-review.yml` does).

**Files:** `.github/workflows/hourly-three-agent-strategy-cycle.yml` (step: GPT independent strategy report)  
**Fix order:** 2  
**Test:** Confirm `.strategy_cycle/gpt.json` is written and passes `validate-agent` after change.

### RC-3 — Gemini `extract_strategy_report.py` `ModuleNotFoundError: learnerbot` (PROVEN)

**Evidence:**  
- Job 96301731834, step 11 logged (at `03:17:35.284Z`):  
  ```
  ModuleNotFoundError: No module named 'learnerbot'
    File "scripts/extract_strategy_report.py", line 8
      from learnerbot.three_agent_strategy_contract import validate_agent_report
  ```
- Gemini CLI ran cleanly (only benign warnings: `256-color support not detected`, `Ripgrep is not available. Falling back to GrepTool.`).  
- The workflow install step runs `pip install -r requirements.txt pytest` but does NOT run `pip install -e .`, so the local `./learnerbot/` directory is not installed into the environment's `site-packages`.

**Root cause:** `scripts/extract_strategy_report.py` imports from the local `learnerbot` package which is only available as a source directory. Without `pip install -e .`, Python cannot resolve the import.

**Impact:** Gemini report is `INCOMPLETE` every cycle even when Gemini CLI produces valid output.

**Corrective action:** Add `pip install -e .` to the "Install review tools" step in `hourly-three-agent-strategy-cycle.yml`. The same fix covers the GPT step's `python -m learnerbot.three_agent_strategy_contract validate-agent` call.

**Files:** `.github/workflows/hourly-three-agent-strategy-cycle.yml` (step: Install review tools), `scripts/extract_strategy_report.py`

### RC-6 — GPT Master concluded `action_required` with 0 jobs (PROVEN)

**Evidence:**  
- Run #32328146903: `status=completed`, `conclusion=action_required`, `created_at=updated_at=run_started_at=03:25:00Z`, 0 jobs listed via `list_workflow_jobs`.  
- PR #108 was authored by `copilot-swe-agent[bot]` — a bot account. GitHub Actions gates workflow runs on bot-authored PRs under the "Require approval for outside collaborators" or environment protection setting.  
- `action_required` with zero jobs elapsed time is the definitive GitHub signal for a workflow blocked before any job is dispatched.

**Root cause:** Repository-level Actions approval setting or an environment protection rule requires manual approval for workflow runs triggered by bot-authored PRs, even from the same repository. No human approved the run.

**Impact:** GPT Master adjudication is permanently blocked until a maintainer manually approves the run. This makes the pipeline non-autonomous whenever Copilot creates the PR.

**Corrective action:** In repository Settings → Actions → General: change "Fork pull request workflows from outside collaborators" from "Require approval for all outside collaborators" to "Require approval for first-time contributors who are new to GitHub" (or trusted-bot exceptions). Alternatively add a `workflow_run` trigger so GPT Master can run on a separate event not subject to the PR approval gate.

**Files:** `.github/workflows/gpt-master-strategy-action.yml`, repository Actions settings  
**Fix order:** 6 (prerequisite for RC-5 resolution)
