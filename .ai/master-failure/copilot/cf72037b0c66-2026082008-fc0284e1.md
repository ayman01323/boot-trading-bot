## Executive summary

The failing stage is the **first PR-resolution step of GPT Master**, before checkout. The observed Master run (`32347179519`) dies in `Resolve latest cycle and completed Copilot report PR from main` because the workflow calls `gh pr list` / `gh pr view` without explicit repository context in a workspace that has not been checked out yet. The log proves this with `failed to run git: fatal: not a git repository`.

PR `#120` does exist, is same-repository, is draft/open, and contains exactly the two expected Copilot report files. However, this audit found **no observed run** of `gpt-master-cycle-dispatcher.yml`, so there is no proof that the dispatcher actually found PR `#120` or dispatched the Master workflow. The dispatcher step also uses pre-checkout `gh` commands without repo scoping, so it likely needs the same fix.

`strategy/latest_status.json` is stale because the hourly cycle writes a waiting snapshot once, and only the successful Master publish step overwrites it with `copilot=DONE`, `three_agent_reports_complete=true`, and `master_decision_available=true`. Since Master never reaches publication, Telegram continues to show the old waiting state.

## Findings

### 1. Proven root cause: Master fails before checkout

- **Stage not completing:** `.github/workflows/gpt-master-strategy-action.yml`, step `Resolve latest cycle and completed Copilot report PR from main`
- **Evidence:**
  - Master run `32347179519` failed in that step.
  - Job log ends with `failed to run git: fatal: not a git repository (or any of the parent directories): .git`.
  - The failing step executes `gh pr list` and `gh pr view` at workflow lines 49-62 before any `actions/checkout`.
- **Why it fails:** `gh pr ...` is running without `GH_REPO` / `-R`, so GitHub CLI tries to infer repo context from git metadata that does not exist yet.
- **Impact:** No checkout, no Copilot report validation, no Codex synthesis, no policy gate, no `master_decision.json`, no ai-reviews publication.
- **Smallest safe fix:** In that step, set `GH_REPO: ${{ github.repository }}` or add `-R "$GITHUB_REPOSITORY"` to both `gh pr view` calls and the `gh pr list` call.
- **Tests:** Extend `tests/test_gpt_master_strategy_reconciler.py` to assert explicit repo scoping for pre-checkout `gh` commands.

### 2. Dispatcher is not proven to have dispatched PR #120

- **Answer:** No — this audit found no observed dispatcher run proving that PR `#120` was found and dispatched.
- **Evidence:**
  - Listing workflow runs for `gpt-master-cycle-dispatcher.yml` returned `total_count=0` during the audit.
  - PR `#120` title includes the exact cycle id, so its title would satisfy the dispatcher's cycle-only search if the workflow ran.
  - The dispatcher step at `.github/workflows/gpt-master-cycle-dispatcher.yml` lines 42-52 also uses `gh pr list` / `gh workflow run` without explicit repo scoping before checkout.
- **Proven vs hypothesis:**
  - **Proven:** no dispatcher run was observed.
  - **Hypothesis with high confidence:** when it does run, it is exposed to the same missing-repo-context failure mode.
- **Smallest safe fix:** Set `GH_REPO: ${{ github.repository }}` for the dispatcher step (or add `-R "$GITHUB_REPOSITORY"` to both `gh` commands).
- **Tests:** Extend `tests/test_gpt_master_cycle_dispatcher.py` to assert explicit repo scoping.

### 3. No later proven failure after Master starts

After the initial PR-resolution bug, this audit found **no proven downstream failure** in checkout, report validation, Codex synthesis, policy gate, or ai-reviews publication, because the workflow never reached those stages. There is one additional high-confidence pre-checkout failure in the same step: even if `copilot_pr_number=120` is supplied, the next `gh pr view` calls would still need explicit repo context.
