## Architecture assessment

The Strategy Lab (`learnerbot/strategy_lab.py`) maintains a clear and enforced safety boundary: all new strategies start in `SHADOW`, preflight simulation and positive-edge checks are required before execution, and AI proposals cannot arm LIVE trading, change capital, or sign transactions. The three-agent contract schema and the `validate_agent_report` / `enforce_master_policy` enforcement are well-designed and correctly prevent auto-deployment of unreviewed changes.

No code changes are proposed in this report. Three SHADOW-improving proposals are raised below.

## Proposals

### COPILOT-STRAT-01 — Calibrated positive-edge forecast gate
**Action:** IMPROVE | **Chains:** SOLANA, EVM | **Confidence:** 0.78

**Hypothesis:** Entries gated on a calibrated expected-value forecast (net of fees, slippage and gas) rather than raw directional signal will reduce loss-making trades and improve profit factor without reducing eligible opportunity participation below 20 %.

**Gap identified:** `strategy_lab.py` defines `MIN_PROFIT_FACTOR = 1.10` and `MIN_ELIGIBLE_PARTICIPATION = 0.20` as post-hoc evaluation thresholds, but there is no pre-entry gate that computes expected net value before committing to a route. AI proposals in `strategy_ai_proposals.py` are accepted into the registry with no calibration check on predicted edge vs. actual recorded costs.

**Shadow test:** Run the enhanced strategy in SHADOW for ≥ 3 evaluation windows, each containing ≥ 8 trades. Pass: profit factor ≥ 1.10 and money-weighted net P&L > 0 after all costs. Fail: profit factor < 1.05 or participation rate < 0.20.

**Research tools needed:** Dune (shadow trade outcomes by strategy family), DEX Screener API (real-time liquidity and fee quotes), Jupiter (Solana route cost simulation).

**Suggested files:** `learnerbot/market_feature_adapter.py`, `learnerbot/strategy_lab_research.py`

### COPILOT-STRAT-02 — Cross-chain cost normalisation before route selection
**Action:** IMPROVE | **Chains:** SOLANA, EVM | **Confidence:** 0.82

**Hypothesis:** Normalising EVM gas costs and Solana priority fees to a common net-P&L unit before route selection will prevent systematically over-selecting the cheaper-quoted but higher-cost chain, improving average trade net P&L.

**Gap identified:** `cross_chain_strategy_signals.py` generates cross-chain signals but does not apply a shared cost-normalisation step; EVM and Solana routes are compared in their native fee units. The profit factor thresholds in `strategy_lab.py` are chain-agnostic but the inputs are not normalised.

**Shadow test:** Run both Solana and EVM shadow strategies through the normalised cost path for ≥ 3 evaluation windows, each containing ≥ 8 trades per chain. Pass: average net P&L per trade improves by ≥ 5 % vs. the preceding window on at least one chain without degrading the other below its current profit factor baseline.

**Research tools needed:** Etherscan API V2 (EVM per-trade gas records), Jupiter (Solana fee quotes), DefiLlama (chain TVL / fee context).

**Suggested files:** `learnerbot/cross_chain_strategy_signals.py`, `learnerbot/shadow_strategy_executor.py`

### COPILOT-STRAT-03 — Enforce minimum sample-size gates before SHADOW promotion
**Action:** SHADOW_MORE | **Chains:** SOLANA, EVM | **Confidence:** 0.88

**Hypothesis:** Enforcing `MIN_EVALUATION_WINDOWS` (3), `MIN_EVALUATION_TRADES` (8) and `MIN_ELIGIBLE_OPPORTUNITIES` (10) as hard, atomic blocking gates in the promotion path will prevent under-sampled strategies from reaching `PROBATION` or `ACTIVE` prematurely, reducing out-of-sample loss events.

**Gap identified:** The three constants are defined at module level in `strategy_lab.py` but the promotion logic does not check all three atomically. A strategy can potentially advance to `PROBATION` through partial window completion. Existing tests in `tests/test_strategy_lab.py` do not cover the edge case where all three thresholds are individually met but the combined atomic check is bypassed.

**Shadow test:** Audit the promotion code path in `strategy_lab.py`. Introduce a regression test that attempts promotion with n=7 trades and asserts it is rejected. Pass: test suite green; no ACTIVE strategy has a window count below `MIN_EVALUATION_WINDOWS`.

**Research tools needed:** Direct code inspection (no external tool required).

**Suggested files:** `learnerbot/strategy_lab.py`, `tests/test_strategy_lab.py`
