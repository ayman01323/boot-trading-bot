## Proposal 1 — `PROP-CSIG-COST-GUARD-001`

**Title:** Cross-chain signal: enforce per-chain cost floor before any positive-edge call
**Action:** IMPROVE
**Chain scope:** SOLANA, EVM
**Confidence:** 0.82
**Priority:** HIGH

### Finding

`cross_chain_strategy_signals.py` computes `net_edge_bps` as `gross_edge_bps` minus the sum of `fees_bps`, `slippage_bps`, `price_impact_bps` and `latency_reserve_bps`. All of these cost fields default to `Decimal('0')` in the `MarketFeatures` dataclass. If a chain adapter has not yet populated them, the signal evaluates a zero-cost phantom edge that passes the positive-edge gate.

This is a correctness risk: `shadow_strategy_executor` can receive a `MarketFeatures` object with all costs zero, creating a shadow trade signal on an unpriced opportunity. For EVM the realistic minimum cost floor is ~10 bps; for Solana ~5 bps.

### Files

- `learnerbot/cross_chain_strategy_signals.py` — add per-chain minimum cost floor
- `tests/test_cross_chain_strategy_signals.py` — new falsifiable test

### Shadow Test (falsifiable)

Inject a `MarketFeatures` with `gross_edge_bps=50`, all cost fields `= 0` for both `SOLANA` and `EVM` chain types. Assert `positive_edge()` returns `False` (or raises `ValueError`) when the minimum cost floor guard is active. Also inject a correctly costed feature set and assert the signal remains `True`.

### Net P&L Impact

Prevents phantom edge from masking unpriced opportunities in shadow mode. Does not reduce opportunity count for correctly costed signals.

## Proposal 2 — `PROP-STRATLAB-PARTICIPATION-FLOOR-002`

**Title:** Strategy Lab: log and surface participation rate when eligible but participation is low
**Action:** IMPROVE
**Chain scope:** SOLANA, EVM
**Confidence:** 0.78
**Priority:** MEDIUM

### Finding

`evaluate_strategy()` in `strategy_lab.py` flags `REWORK` when `profit_factor < MIN_PROFIT_FACTOR` but does not produce a structured log or metric when a strategy's participation rate is below `MIN_ELIGIBLE_PARTICIPATION` (0.20). The hourly review loop cannot distinguish a strategy that sees many eligible opportunities but ignores them from one that simply sees none.

Adding a `participation_rate` field to the metrics dict and a `WARNING` log entry when participation is below the floor will enable targeted filter rework recommendations without requiring manual log inspection.

### Files

- `learnerbot/strategy_lab.py` — add `participation_rate` metric and warning
- `tests/test_strategy_lab_participation.py` — new test

### Shadow Test (falsifiable)

Create `strategy_lab_windows` records with `eligible_opportunities=20`, `participated=1` (5%). Call `evaluate_strategy()` and assert the returned dict contains `participation_rate=Decimal('0.05')` and a status/warning for low participation. Verify that `participated=5` (25%) does not trigger the warning.

### Net P&L Impact

No direct P&L change. Enables diagnostic visibility that prevents profitable opportunities from being silently suppressed by over-restrictive filters.

## Proposal 3 — `PROP-FORECAST-CALIBRATION-003`

**Title:** Research: add calibration check (Brier score) before trusting forecast_positive_edge_probability
**Action:** RESEARCH_MORE
**Chain scope:** SOLANA, EVM
**Confidence:** 0.75
**Priority:** MEDIUM

### Finding

`MarketFeatures.forecast_positive_edge_probability` is consumed directly in `cross_chain_strategy_signals.py` without any calibration evidence. `FORECAST_RESEARCH_SPEC` in `strategy_lab_research.py` explicitly requires a calibration metric (Brier score or log loss) but there is no enforcement mechanism in the evaluation path. An uncalibrated forecast with stated high probability can inflate participation in low-edge periods.

### Research Plan

1. Collect shadow execution outcomes with recorded forecast probabilities for both Solana and EVM chains over ≥ 50 events per chain.
2. Compute rolling Brier score and compare to naive baseline (always predict 0.5).
3. If Brier score < 0.25 **and** shadow P&L is positive, proceed to an `IMPROVE` proposal for calibration-gated forecasting.

### Research Tools

- **Dune** — query shadow DEX trade outcomes by chain and time window
- **DEX Screener API** — cross-reference pool/token quality for feature context
- **Jupiter** — Solana route/quote research for shadow cost validation

### Shadow Test (falsifiable)

After ≥ 50 shadow outcomes per chain: compute rolling Brier score for `forecast_positive_edge_probability`. Assert Brier score < 0.25 before any strategy is allowed to use forecast gating. Document chain-specific and market-regime-separated results.

### Net P&L Impact

Cannot be quantified without calibration data. Reduces risk of phantom-edge trades driven by an uncalibrated forecast model.
