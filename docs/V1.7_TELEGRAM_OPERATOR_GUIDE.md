# Multi-Chain Learning Bot v1.7 — Telegram Operator Guide

## Purpose

v1.7 turns Telegram from a report-only interface into an authorised **operator input interface**. It writes only a defined allow-list of settings to the CSV configuration files. The main learning loop hot-reloads those changes.

## Main Telegram controls

Open:

```text
/menu
```

Then choose **⚙️ Operator Control**.

You can control:

- learning engine ON / PAUSED;
- SHADOW / ARMED recommendation mode;
- enabled chains;
- eligible arbitrage behaviours;
- maximum input;
- canary input;
- minimum conservative profit;
- copy sizing percentage;
- follower edge-capture assumption;
- maximum signal age;
- minimum copy score.

## Direct commands

```text
/control
/engine on
/engine off
/mode shadow
/mode armed
/setmax 0.25
/setprofit 0.001
/setcopy 25
/setedge 50
/setage 2
/setcanary 0.05
/setscore 65
/queue
```

If a numeric command is sent without a value, the bot asks for the value in the next Telegram message. `/cancel` cancels the pending input.

## Modes

### SHADOW

The bot keeps scanning, learning, ranking and producing IN/OUT recommendations. No recommendation is queued for execution.

### ARMED

Only a recommendation that is already `IN` after all configured gates can be written to:

```text
CSVbot/auto/execution_queue.csv
```

The queue is de-duplicated by recommendation ID.

**ARMED is not transaction signing.** v1.7 has no private key and does not broadcast a blockchain transaction.

## Telegram security model

Only chat IDs in `TELEGRAM_CHAT_IDS` are authorised. There can be up to five IDs under the current configuration loader.

Operator changes are written to:

```text
CSVbot/auto/telegram_operator_audit.csv
```

Set this locally to stop Telegram changing operator settings:

```csv
setting,value,description
telegram_write_enabled,false,Disable Telegram operator setting changes
```

in `CSVbot/operator_settings.csv`.

## Execution queue security rule

A separate local executor should consume a queue row only after it independently:

1. refreshes the pool state;
2. obtains a new exact quote;
3. re-simulates the whole transaction;
4. checks liquidity and sellability;
5. checks the route and all router/contract addresses against an allow-list;
6. enforces a maximum capital limit;
7. enforces an on-chain minimum-profit/revert condition;
8. signs locally, never through Telegram.

## Recommended first use

Keep:

```text
/mode shadow
```

until the live opportunity feed is producing current quotes and simulations. `CSVbot/live_opportunities.csv` remains the current input boundary for those live checks.
