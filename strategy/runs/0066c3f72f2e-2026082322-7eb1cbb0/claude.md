# Claude strategy review

No runtime forensics were supplied (evidence_status=MISSING_RUNTIME_FORENSICS), so this is a static architecture review only; no claim is made about current live profitability, canary readiness, or realized P&L. The bot runs two independently-matured stacks (EVM and Solana) built around leader/copy-trading (SiBot/SiMo) plus EVM cyclic-arbitrage route scanning, layered under ~150-200+ runtime monkeypatch modules chained from learnerbot/__main__.py. Explicit gross-vs-net P&L accounting exists (profit.py, fee_engine.py, sibot.py evaluate_position/close_position), and pre-trade slippage/price-impact caps and gas-multiple floors are enforced before execution. The strongest gap for money-weighted NET P&L accuracy is that exit-decision thresholds (stop-loss/take-profit/trailing) compare against P&L net of gas but not net of the platform profit-share fee, which is only deducted after realization — this can misstate the true net-to-user economics that drive exit timing. A second material gap is that the most rigorous net-edge model (cross_chain_strategy_signals.py, which nets fees, slippage, price impact, AND a latency_reserve_bps term) is SHADOW-only and disconnected from the live execution path; live trading instead relies on older, less complete per-module ad hoc slippage/impact checks with no latency or MEV cost term. Risk controls are asymmetric across chains: EVM has standing portfolio-level daily-loss and drawdown circuit breakers (sibot_profit_guard_patch.py); Solana's only portfolio-level halt precedent was a one-off manual migration script, not a standing automatic control, leaving Solana to rely solely on per-position stops and fault-count circuit breakers. Observability is likewise asymmetric: per-stage execution latency instrumentation (execution_latency.py) is wired in for Solana only; EVM has no equivalent, and a purpose-built RPC health/latency diagnostic (scripts/rpc_health_audit.py) exists but is not called by any runtime path, systemd unit, or workflow, so it produces no continuous data. A likely EVM execution-reliability issue (not a strategy issue) was also found: nonce is re-fetched as 'pending' per transaction with no local serialized nonce manager, which is a known pattern for nonce collisions under any concurrent submission path. All findings below are derived from static code reading against an architecture-only evidence packet; none are confirmed against live traces, and none should be read as claims about current realized performance.
